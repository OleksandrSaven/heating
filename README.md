# Heating Automation 2026

Система автоматизації опалення приватного будинку на базі **Spring Boot, Vaadin, MQTT та ESP32**.

> Проєкт призначений для моніторингу й подальшої автоматизації котельні: твердопаливного та електричного котлів, теплоакумулятора, бойлера непрямого нагріву, радіаторного опалення й теплої підлоги.

## Можливості

- Візуальна схема котельні у вебінтерфейсі Vaadin.
- Відображення температур подачі та зворотки котлів.
- Моніторинг температур теплоакумулятора на різних рівнях.
- Відображення температур контурів радіаторів і теплої підлоги.
- Моніторинг бойлера гарячого водопостачання.
- Індикація стану насосів і запитів на тепло.
- Кольорове попередження для температур, що виходять за задані межі.
- Запланована інтеграція пристроїв через MQTT.
- Можливість розширення для керування обладнанням через ESP32.

## Технології

- Java 21
- Spring Boot

## Температурні індикатори

У схемі котельні передбачено кольорове відображення вибраних температур.

| Параметр | Попередження | Аварійний колір |
|---|---:|---:|
| Подача твердопаливного котла | від 80 °C | від 90 °C |
| Димові гази | від 180 °C | понад 200 °C |
| Подача теплої підлоги | від 30 °C | понад 35 °C |
| Зворотка твердопаливного котла | поза 55–65 °C | нижче 50 °C або вище 70 °C |

Для зворотки твердопаливного котла:
- **55–65 °C включно** — нормальний діапазон;
- **50–55 °C або 65–70 °C** — попередження поза нормальним діапазоном;
- **нижче 50 °C або вище 70 °C** — аварійна індикація.

Пороги є налаштуваннями індикації інтерфейсу. Їх слід перевірити й узгодити з документацією конкретного котла та системи.

## Вимоги

Для локального запуску потрібні:

- JDK 21;
- Maven або Maven Wrapper (`mvnw`);
- PostgreSQL, якщо база даних використовується поточною конфігурацією;
- Mosquitto, якщо MQTT-інтеграція ввімкнена;
- Git.

## Запуск

1. Клонуйте репозиторій:

   ```bash
   git clone <URL_ВАШОГО_РЕПОЗИТОРІЮ>
   cd heating-automation2026
   ```

2. Переконайтеся, що встановлено Java 21:

   ```bash
   java -version
   ```

3. Налаштуйте параметри середовища — підключення до БД, MQTT та інші секрети — відповідно до конфігурації застосунку. Не зберігайте паролі й токени в Git.

4. Запустіть застосунок через Maven Wrapper, якщо він є в репозиторії:

   ```bash
   ./mvnw spring-boot:run
   ```

   Або через встановлений Maven:

   ```bash
   mvn spring-boot:run
   ```

5. Відкрийте адресу, визначену конфігурацією застосунку. Маршрут схеми котельні у поточній реалізації: `/boiler-room`.

Якщо проєкт використовує Docker Compose для PostgreSQL або Mosquitto, спочатку запустіть відповідні сервіси згідно з вашим `docker-compose.yml`.

## Конфігурація

Перед запуском перевірте файли конфігурації в `src/main/resources` та налаштуйте параметри для свого середовища.

Рекомендовано використовувати змінні середовища для секретів, наприклад:

```text
SPRING_DATASOURCE_URL
SPRING_DATASOURCE_USERNAME
SPRING_DATASOURCE_PASSWORD
MQTT_BROKER_URL
MQTT_USERNAME
MQTT_PASSWORD
```

Назви змінних потрібно узгодити з реальною конфігурацією застосунку — наведений список є прикладом, а не гарантією, що всі ці змінні вже підтримуються кодом.

## Безпека та експлуатація

- Не комітьте паролі, токени, приватні ключі чи реальні секрети.
- Не відкривайте MQTT-брокер або панель керування в інтернет без належної автентифікації та мережевих обмежень.
- Перевіряйте стан датчиків і зв'язку з пристроями.
- Застосунок і його вебінтерфейс не повинні бути єдиним засобом захисту котла.
- Аварійне вимкнення, захист від перегріву та керування насосами мають працювати незалежно від вебінтерфейсу, БД і MQTT.
- Будь-які зміни алгоритмів керування перевіряйте безпечно, перш ніж підключати до реального обладнання.

## Поточний стан
